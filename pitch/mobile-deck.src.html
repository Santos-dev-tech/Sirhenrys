Where this started

We flagged this ourselves

“The console is desktop-shaped. Shop floor staff carry phones. The till works on one; the tables do not.” Our own audit of the build, section G

That note was right about the problem and too kind about the severity. When we went back and measured rather than looked, the till did not work on a phone either. Neither did the shop front.

This deck is that correction, and the fix.

The finding

The top of the page would not shrink

575px Space the header demanded
375px Space a phone has

A menu button, the wordmark and six icons in a row that was never allowed to get smaller. When a phone browser meets a page that will not fit, it does the only thing it can: it zooms the entire page out until the widest thing fits — to 607px, on a 375px screen.

Everything sized in percentages then measured itself against that 607px instead of the real screen. That is why the slide-out menu came out 425px wide on a 375px phone — a menu wider than the device it was drawn on.

How we know it stays fixed

The checks now run every time

Two of these problems had already passed a test suite while being broken. So the tests changed too, not just the code.

5

Phone widths, every screen

430, 390, 375, 360 and 320px — the shop front and the staff console, on every page.

31

Checks on the till alone

It signs in through the real two-step staff login and reads the layout the browser actually produced.

56

Security and interface checks

The existing suite, still passing, plus colour contrast in both light and dark.

The old tests measured the page against itself, so a page that had zoomed out always “fitted”. They now measure it against the physical width of the phone, which is the only number that matters to a customer.

Being straight with you

What this does not fix

Four things a phone still deserves, none of them touched by this work.

  • 1
    Image weight. A phone on a Nairobi mobile connection still downloads the same full-size photographs a desktop does. This is the single biggest remaining cost to a shopper on data, and it is mechanical work rather than a redesign.
  • 2
    The till still needs a connection. A till that stops when the signal drops is a till that stops the queue. The groundwork is there; finishing it is a separate piece.
  • 3
    M-Pesa is still simulated. Unchanged by this work, and still the case as pitched.
  • 4
    Staff sign-in is still demo-grade. The console says so on screen, on every page, until it is switched to real staff accounts.

Anyone who tells you a system is finished has not built one.
